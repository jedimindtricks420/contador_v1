## 1. Описание продукта

**Contador** — облачная система автоматизированного бухгалтерского учёта для малого и среднего бизнеса Республики Узбекистан, работающая в соответствии с **НСБУ №1** (рег. МЮ №3544, с 01.01.2025) и **НСБУ №21** (рег. МЮ №3593, с 01.01.2025).

### Ключевые характеристики

- **Автоматическая классификация** банковских транзакций через AI (GPT-4o-mini) и движок правил
- **Документо-центричная** модель учёта: каждая хозяйственная операция — документ с шаблоном проводок
- **7-шаговый мастер** закрытия месяца: импорт → классификация → начисления → курсовые разницы → Soliq → финализация → блокировка
- **Полная финансовая отчётность:** Форма №1 (Баланс, стр. 010–780) + Форма №2 (P&L, стр. 010–270)
- **Два налоговых режима:** VAT (НДС 12% + прибыль 15%) и TURNOVER_TAX (1–4%, настраивается на уровне орг.)
- **Multi-tenant**: одна БД, полная изоляция данных на уровне приложения

## 3. Функциональные возможности (реализованы)

### Модуль A — Импорт банковской выписки
- Парсинг 1CClientBankExchange (.txt) и Excel (.xlsx) — форматы Asaka, Kapital, Ipak Yoli
- SHA-256 дедупликация транзакций
- Preview первых 5 строк перед импортом
- Пакетный откат по `importBatchId`
- Импорт выписок Soliq (`my.soliq.uz`)

### Модуль B — Классификация операций
- Движок правил: INN, KEYWORD, AMOUNT_RANGE, TREASURY_ACCOUNT (in-memory кэш 30 сек)
- AI-классификатор: GPT-4o-mini, батчи по 20, порог уверенности 70%
- Очередь уточнений (NEEDS_CLARIFICATION) с группировкой по контрагенту

### Модуль C — Реестр транзакций и документов
- Просмотр и ручная корректировка `StagedTransaction`
- Изменение типа документа, пропуск / отмена пропуска
- Фильтры: период, статус, поиск

### Модуль D — Открытые позиции
- Мониторинг авансов, подотчётных сумм, депозитов, займов
- Автоматический статус RISK при истечении дедлайна
- Ручное закрытие и повторное открытие

### Модуль E — Закрытие месяца (7 шагов)

| Шаг | Действие |
|-----|---------|
| 1 | Импорт выписки |
| 2 | AI-классификация |
| 3 | Реестр документов |
| 4 | Начисления (ФОТ, амортизация, аренда) |
| 5 | Курсовые разницы (курс ЦБ РУз) |
| 6 | Сверка с Soliq (ЭСФ) |
| 7 | Финализация: налоги → PERIOD_CLOSING → блокировка |

**Финализация (Step 7):**
- VAT-режим: начисляет PROFIT_TAX_ACCRUAL (Дт 9810 → Кт 6410, 15%)
- TURNOVER_TAX: начисляет TURNOVER_TAX_ACCRUAL (Дт 9810 → Кт 6410, ставка из `org.turnoverTaxRate`)
- Создаёт PERIOD_CLOSING (закрывает 9xxx → 9910)
- Блокирует период (`Period.status = CLOSED`)
- Создаёт TaxCalendarEvent на 20-е следующего месяца

**Годовое закрытие** (`POST /api/closing/year-end`, только декабрь):
- Переносит 9910 → 8710 (прибыль) / 8710 → 9910 (убыток)
- Документ `YEAR_END_CLOSE`

### Модуль F — Дашборды и мониторинг
- Главный дашборд: KPI-блоки, налоговый календарь, открытые риски
- Cashflow: движение по расчётным счетам
- Управление банковскими счетами

### Модуль G — Финансовая отчётность

**Форма №1 — Бухгалтерский баланс** (`GET /api/reports/balance?to=YYYY-MM-DD`):
- Полный набор строк 010–780 по НСБУ №21
- Кумулятивные SQL-агрегаты по все JournalEntry ≤ endDate
- Строка 450 = `balCredit(8710) + transitNet` (transitNet — незакрытый текущий финрезультат)
- Балансовый контроль: `|line400 − line780| ≤ 1`

**Форма №2 — Отчёт о финансовых результатах** (`GET /api/pnl?from=&to=`):
- Полный набор строк 010–270 по НСБУ №21
- Обороты JournalEntry за период, исключая PERIOD_CLOSING
- Динамическая подпись строки 250 по налоговому режиму

**Прочие отчёты:**
- ОСВ (оборотно-сальдовая ведомость) с субаналитикой
- Журнал проводок
- Карточка счёта
- Субконто (анализ по контрагентам)
- Анализ счёта (корреспонденции)

### Модуль H — Движок проводок
- Единственная точка создания JournalEntry: `postDocument()`
- Шаблонные проводки с expression evaluator (Decimal.js)
- Атомарные транзакции + Σ Дт = Σ Кт
- Post / Void / Repost

### Модуль I — Аутентификация
- JWT (jose, HS256), HTTP-only cookie `v2_session`, 7 дней
- Регистрация, логин, logout, сброс пароля (email)
- Edge Runtime middleware на всех маршрутах кроме публичных

### Модуль J — Настройки
- Настройки организации: налоговый режим, `turnoverTaxRate` (1–4%), AI-порог
- CRUD правил классификации с приоритетами
- Налоговый календарь и шаблоны дедлайнов

## 5. Технические ограничения

- **Глобальный план счетов**: таблица `Account` без `orgId` — счета общие для всех организаций (214 счетов НСБУ)
- **Один инстанс AI**: нет per-org изоляции очередей классификации
- **SQLite не поддерживается**: требуется PostgreSQL 16+
- **Нет SSO/OAuth**: только email + password авторизация
- **Биллинг**: реализован частично — только через Admin-панель (Payme/Click не активированы в v2 UI)
- **Email-уведомления**: не активированы на продакшн-сервере

## 6. Глоссарий

| Термин | Определение |
|--------|-----------|
| **StagedTransaction** | Импортированная банковская транзакция до её проведения |
| **Document** | Проведённый хозяйственный документ с JournalEntry |
| **JournalEntry** | Бухгалтерская проводка (счёт Дт/Кт, сумма, дата, контрагент) |
| **OpenItem** | Открытая позиция на буферном счёте (аванс, подотчёт, депозит) |
| **Period** | Учётный период (год + месяц), статус OPEN / CLOSED |
| **PostingTemplate** | JSON-шаблон, описывающий строки проводок документа |
| **importBatchId** | UUID пакета импорта, объединяет транзакции для откат |
| **transitNet** | Кт − Дт всех TRANSIT-счетов (9xxx) — незакрытый финрезультат текущего года |
| **НСБУ** | Национальные стандарты бухгалтерского учёта РУз |
| **ОСВ** | Оборотно-сальдовая ведомость |
| **ФОТ** | Фонд оплаты труда |
| **ЦБ РУз** | Центральный банк Республики Узбекистан |
| **НДФЛ** | Налог на доходы физических лиц (12%) |
| **ИНПС** | Индивидуальный накопительный пенсионный счёт (0.1%) |
| **Soliq** | Налоговый орган РУз, портал my.soliq.uz |
| **ЭСФ** | Электронный счёт-фактура (через Soliq) |
| **PERIOD_CLOSING** | Системный документ — закрытие TRANSIT-счетов в конце месяца |
| **YEAR_END_CLOSE** | Системный документ — перенос 9910 → 8710 в конце года |
