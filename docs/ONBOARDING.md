# Онбординг и отраслевые шаблоны

## Процесс онбординга (3 шага)

Реализован как State Machine — состояние хранится в поле `onboarding_state` модели `Organization`.

### Шаг 1 — `BASIC_INFO`
Пользователь вводит название компании и ИНН. Создаётся запись в таблице `Organization`.

### Шаг 2 — `ACCOUNTING_SETTINGS`
Настройка учётной политики:
- `opening_balance_date` — дата ввода начальных остатков
- `closed_period_date` — дата закрытого периода (до неё нельзя редактировать проводки)

### Шаг 3 — `SELECT_INDUSTRY`
Выбор плана счетов. Два варианта:

| Вариант | Действие | Режим API |
|---|---|---|
| **Полный план счетов** | Активирует все 340 счетов из `MasterAccount` | `mode=full` |
| **Шаблон по отрасли** | Активирует счета выбранной отрасли из `IndustryTemplate` | `mode=template` |

API: `POST /api/onboarding/apply-template`

После завершения `onboarding_state` переходит в `COMPLETED`.

## Механизм активации счетов

При выборе отрасли (`mode=template`):
1. Находятся все записи `IndustryTemplateItem` для выбранного шаблона.
2. Для каждого счёта из шаблона вызывается `upsert` в таблицу `Account`:
   - Если счёт уже существует — устанавливается `is_active: true`.
   - Если счёта нет — создаётся копия из `MasterAccount`.
3. AI автоматически добавляет отсутствующие счета при вводе проводок (`is_missing: true` → `upsert` в `execute/route.ts`).

При полном плане (`mode=full`):
1. Берутся все 340 записей из `MasterAccount`.
2. Для каждой — `upsert` в `Account` организации.

## Добавление счетов после онбординга

Пользователь может активировать дополнительные счета в **Настройки → Счета**:
- Выбрать из полного списка НСБУ (340 позиций).
- Деактивировать счёт нельзя, если по нему есть транзакции или он помечен обязательным в шаблоне.
