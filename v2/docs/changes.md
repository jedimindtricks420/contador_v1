### BUG-01 — Исправить НДФЛ в `SALARY_ACCRUAL`

**Проблема:**

В `v2/src/lib/constants.ts` сейчас:

- `NDFL = 0.12`
- `NDFL_BUDGET = 0.12`
- `INPS = 0.001`

Комментарий в коде прямо говорит, что общий НДФЛ = бюджетная часть + ИНПС. При текущих значениях удержание получается **12.1%**, а не 12%.

**Что изменить:**

1. В `v2/src/lib/constants.ts`:
   - `NDFL_BUDGET` изменить с `0.12` на `0.119`.
   - `NDFL` оставить как общий налог `0.12`.
2. В `v2/src/lib/ensureBaseData.ts`:
   - `SALARY_ACCRUAL` должен считать проводку по НДФЛ из `TAX_RATES.NDFL_BUDGET = 0.119`.
3. В `v2/src/lib/closing.ts`:
   - `NET_SALARY_RATE` должен стать `1 - 0.12 = 0.88`, то есть по формуле `1 - NDFL_BUDGET - INPS`.
4. Обновить `v2/docs/modules/module_DOCUMENT_TYPES.md`.
5. Добавить тесты на расчёт начисления зарплаты и нетто-выплаты.

**Критерий приёмки:**

- при `salaryAmount = 1_000_000`:
  - НДФЛ в бюджет = `119_000`
  - ИНПС = `1_000`
  - чистая зарплата = `880_000`

## 5. Сквозные требования ко всем изменениям

Это обязательные правила реализации для каждого исправления и каждого нового типа.

### 5.1. Код и сидирование

- Все новые типы добавлять через `baseDocumentTypes` в `v2/src/lib/ensureBaseData.ts`.
- Сидирование должно быть идемпотентным.
- Нельзя дублировать коды документов.

### 5.2. AI-классификация

Для каждого `BANK_AUTO` типа обязательно:

1. определить направление:
   - только входящий (`CREDIT_ONLY_CODES`)
   - только исходящий (`DEBIT_ONLY_CODES`)
   - либо явно двусторонний сценарий, если он действительно нужен;
2. обновить промпт/описания категорий;
3. не возвращать устаревшие типы (`SUPPLIER_PAYMENT` как legacy оставить вне рекомендаций).

### 5.3. Typed payloads

Для всех новых и исправляемых типов убрать неструктурированный `any`, насколько это затрагивается изменением:

- валидация payload на входе;
- явные поля для сумм, счетов и режимов;
- отказ от неявных полей типа «всё в amount» там, где нужна структура.

Минимум это касается:

- `FIXED_ASSET_SALE`
- `DIVIDEND_PAYMENT`
- `CUSTOMS_DUTY`
- `INTERNAL_TRANSFER_RECEIVED`
- `GOODS_RETURNED_FROM_CUSTOMER`
- `CORRECTIVE_INVOICE_*`
- `FIXED_ASSET_REVALUATION`

### 5.4. Документация

Обновлять нужно **именно**:

- `v2/docs/modules/module_DOCUMENT_TYPES.md`

`docs/DOCUMENT_TYPES.md` сейчас является ссылочным/обёрточным файлом, поэтому источник истины должен поддерживаться в `v2/docs/modules/module_DOCUMENT_TYPES.md`.

### 5.5. Тесты

Минимальный обязательный набор:

1. unit/integration test на проводку каждого нового типа;
2. test на `voidDocument()` и `repostDocument()` для затронутых типов;
3. tests на отчёты Form 1 / Form 2 для изменённых счетов и строк;
4. tests на закрытие периода при новых типах, если они участвуют в closing.
