**П1.1 — SALARY_ACCRUAL: неверная ставка НДФЛ** [АУДИТ — подтверждён в constants.ts]

**Источник:** Статья 385 НК РУз: «Исчисленная сумма налога уменьшается на сумму обязательных взносов на индивидуальные накопительные пенсионные счета».

Код в `constants.ts` содержит комментарий «НДФЛ = НДФЛ_BUDGET + INPS», то есть бюджетная часть должна быть 11.9%, но константа `NDFL_BUDGET` при этом равна `0.12`. Из зарплаты сотрудника фактически удерживается 12% + 0.1% = 12.1%, а не 12%. Сотрудник систематически переплачивает 0.1% от зарплаты.

| | Сейчас (неверно) | Должно быть |
|--|------------------|-------------|
| constants.ts `NDFL_BUDGET` | `0.12` | `0.119` |
| Строка НДФЛ в SALARY_ACCRUAL | `6710 Дт — 6410 Кт: salary × 0.12` | `6710 Дт — 6410 Кт: salary × 0.119` |
| Строка ИНПС | `6710 Дт — 6530 Кт: salary × 0.001` | без изменений ✓ |

Чистая выплата сотруднику: `salary × (1 − 0.119 − 0.001) = salary × 0.88`

**Файлы:** `v2/src/lib/constants.ts:2-6`, `v2/src/lib/ensureBaseData.ts:281-300`

### Н2 — Валидация увязки 8710 при годовом закрытии

**Файл:** `v2/src/lib/closing.ts:346-393`

`YEAR_END_CLOSE` переносит `9910 → 8710` без проверки правильности итогового сальдо счёта 8710. Возможна ситуация, когда 8710 на конец года расходится с ожидаемым значением из-за некорректно проведённых дивидендов, корректировок или пропущенных операций.

**Исправление:** добавить pre-close validation перед созданием `YEAR_END_CLOSE`:

```typescript
// В finalizePeriod() для декабря:
const openingBalance8710 = await getAccountBalance("8710", startOfYear)
const netProfit = await getNetProfit(year)           // 9910 кредитовый остаток
const dividendsPaid = await getDividendsPaid(year)   // сумма по 6610 → 5110 за год

const expected8710_end = openingBalance8710.plus(netProfit).minus(dividendsPaid)
const actual8710_end = await getAccountBalance("8710", endOfYear)

if (!expected8710_end.eq(actual8710_end)) {
  throw new YearEndValidationError({
    message: "Расхождение счёта 8710 (нераспределённая прибыль)",
    expected: expected8710_end,
    actual: actual8710_end,
    diff: actual8710_end.minus(expected8710_end)
  })
}
```

**Приоритет: Критично** — без этого годовое закрытие не гарантирует целостность капитала.

### Н3 — Налог на дивиденды: удержание НДФЛ 5% у источника выплаты

| 6610 (Дивиденды к уплате) | 5110 (Банк) | dividendAmount × 0.95 | Чистая выплата |

После выплаты отдельно создаётся `TAX_PAYMENT` для перечисления удержанного НДФЛ в бюджет: `6410 Дт — 5110 Кт`.

**Приоритет: MVP** — каждая выплата дивидендов без удержания НДФЛ является нарушением НК.

### Н4 — Silent-fail tax calendar sync: ошибки без rollback

**Файл:** `v2/src/lib/posting/postingEngine.ts` (и смежные)

```typescript
// Вместо:
await prisma.document.update({ status: 'posted', ... })

// Должно быть:
await prisma.$transaction(async (tx) => {
```

**Приоритет: Критично** — silent desync между проводками и налоговым календарём трудно обнаружить и исправить ретроактивно.

```
Приоритет матчинга (убывающий):
1. Exact amount match + exact counterparty + exact invoice reference
2. Exact amount match + exact counterparty (берётся самая свежая открытая позиция)
3. Amount within tolerance (±0.5% для курсовых расхождений) + counterparty
4. Amount match без counterparty → NEEDS_CLARIFICATION
5. Partial amount (сумма < open item) → UI-диалог выбора позиции
6. При неоднозначности → статус NEEDS_CLARIFICATION, не молчаливый матч
```

**Исправление:**
```typescript
type MatchResult =
  | { status: 'matched'; openItemId: string; confidence: 'exact' | 'fuzzy' }
  | { status: 'needs_clarification'; candidates: OpenItem[] }
  | { status: 'no_match' }
```
AI-классификатор и движок правил не должны автоматически провоить документ при статусе `needs_clarification`.

**Приоритет: Высокий** — некорректный матчинг приводит к закрытию не той позиции и ошибкам в ОСВ.

### Н12 — Idempotency закрытия: нет state machine и журнала отказов

**Файл:** `v2/src/lib/closing.ts`

Повторный запуск `finalizePeriod()` для уже закрытого или находящегося в процессе закрытия периода не имеет формальной защиты через state machine. Возможны race conditions и двойное создание документов закрытия.

**Исправление:**

```typescript
type ClosingStatus = 'idle' | 'running' | 'completed' | 'failed'

// Переходы допустимы только:
// idle → running (при запуске)
// running → completed (успех)
// running → failed (ошибка)
// failed → running (retry)
// completed → (нет перехода) — повторный запуск = ошибка

async function finalizePeriod(orgId, periodId) {
  const job = await acquireClosingLock(orgId, periodId) // upsert с статусом RUNNING
  if (!job) throw new ClosingAlreadyRunningError()

  try {
    await runClosingSteps(job)
    await markCompleted(job.id)
  } catch (e) {
    await markFailed(job.id, e.message)
    throw e
  }
}
```

Каждый шаг закрытия логируется в `ClosingJob.log` (JSONB) с временной меткой и результатом. Это даёт журнал причин отказа без необходимости читать логи сервера.

**Приоритет: Высокий** — без state machine повторный клик «Закрыть период» в UI может создать дубликаты документов.

### Н13 — Typed payloads: системная замена `any` по всем типам документов

**Файл:** `v2/src/lib/posting/postingEngine.ts`, `v2/src/lib/ensureBaseData.ts`

Gap-матрица указывает: `postDocument` и смежные функции используют `any` для payload, что не позволяет выявлять ошибки типизации до runtime.

**Исправление:** создать дискриминированный union типов:

```typescript
type DocumentPayload =
  | { code: 'SALARY_ACCRUAL'; salaryAmount: Decimal; employeeId: string }
  | { code: 'GOODS_RECEIVED'; amount: Decimal; vatAmount: Decimal; counterpartyId: string }
  | { code: 'FX_DIFFERENCE'; accountCode: string; fxDifference: Decimal; rate: Decimal }
  | { code: 'FIXED_ASSET_SALE'; amount: Decimal; isVatPayer: boolean }
  // ... для каждого из 65 типов

function postDocument(payload: DocumentPayload): Promise<Document>
```

Это также позволит TypeScript автоматически проверять, что все обязательные поля переданы при создании документа.

**Приоритет: Средний** — не блокирует MVP, но критично для долгосрочной поддержки.
