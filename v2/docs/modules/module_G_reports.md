## G1. Форма №2 — Отчёт о финансовых результатах

**Файл:** `src/app/api/pnl/route.ts`  
**Страница:** `src/app/pnl/PnLClient.tsx`  
**API:** `GET /api/pnl?from=YYYY-MM-DD&to=YYYY-MM-DD`

Полная реализация строк 010–270 по НСБУ №21.

### Источник данных

Прямые SQL-агрегаты оборотов JournalEntry за период, **исключая PERIOD_CLOSING** (во избежание задваивания):

```sql
AND dt.code != 'PERIOD_CLOSING'
```

### Строки Формы №2

| Строка | Наименование | Счета / Формула |
|--------|-------------|----------------|
| 010 | Чистая выручка от реализации | Кт(9010+9020+9030) − Дт(9040+9050) |
| 020 | Себестоимость реализованной продукции | Дт(9110+9120+9130) — 9130 только для услуг, **проданных** клиентам; покупка услуг у поставщика (`SERVICE_RECEIVED`) пишет на 9420 (стр.060), не сюда |
| **030** | **ВАЛОВАЯ ПРИБЫЛЬ** | **010 − 020** |
| 050 | Расходы по реализации | Дт(9410) |
| 060 | Административные расходы | Дт(9420) |
| 070 | Прочие операционные расходы | Дт(9430) |
| 080 | Расходы, вычитаемые в будущем | Дт(9440) |
| 040 | Расходы периода, итого | 050+060+070+080 |
| 090 | Прочие доходы от основной деятельности | Кт(9310–9390) |
| **100** | **ПРИБЫЛЬ ОТ ОСНОВНОЙ ДЕЯТЕЛЬНОСТИ** | **030 − 040 + 090** |
| 120 | Доходы — дивиденды | Кт(9520) |
| 130 | Доходы — проценты | Кт(9530) |
| 140 | Доходы — фин. аренда | Кт(9550) |
| 150 | Доходы — курсовые разницы (+) | Кт(9540) |
| 160 | Прочие доходы фин. деятельности | Кт(9510+9560+9590) |
| 110 | Доходы от фин. деятельности, итого | 120+130+140+150+160 |
| 180 | Расходы — проценты | Дт(9610) |
| 200 | Убытки курсовых разниц | Дт(9620) |
| 210 | Прочие расходы фин. деятельности | Дт(9630+9690) |
| 170 | Расходы по фин. деятельности, итого | 180+200+210 |
| **220** | **ПРИБЫЛЬ ОТ ОБЩЕХОЗЯЙСТВЕННОЙ ДЕЯТЕЛЬНОСТИ** | **100 + 110 − 170** |
| 230 | Чрезвычайные прибыли и убытки | Кт(9710) − Дт(9720) |
| **240** | **ПРИБЫЛЬ ДО УПЛАТЫ НАЛОГА** | **220 ± 230** |
| 250 | Налог на прибыль / налог с оборота | Дт(9810) − Кт(9810) → fallback TaxCalendarEvent |
| 260 | Прочие налоги от прибыли | Дт(9820) |
| **270** | **ЧИСТАЯ ПРИБЫЛЬ** | **240 − 250 − 260** |

### Строка 250 — логика фолбэка

Если нетто `Дт(9810) − Кт(9810) = 0` → сумма налога берётся из `TaxCalendarEvent` (плановые суммы периода).

Нетто (а не только дебет) — из-за квартальной логики налога на прибыль (2026-07-10):
`PROFIT_TAX_REVERSAL` кредитует 9810, когда накопленная с начала года база упала
после убыточного квартала, и строка 250 должна уменьшаться. Кредиты реформации
(PERIOD_CLOSING) в выборку P&L не попадают — они исключены на уровне SQL.
Для VAT-организаций стр. 250 заполняется по квартальным месяцам (3/6/9/12) —
отчётный период по налогу на прибыль квартальный (ст. 338 НК), см. `module_E_closing.md`.

> ⚠️ Строка 250 всегда берётся из счёта **9810**, независимо от `org.taxRegime` — и налог на прибыль, и налог с оборота проходят через один и тот же счёт (см. таблицу выше). Счёт 9820 — самостоятельная строка 260, не альтернатива 9810. Это уточнение появилось после того, как `TURNOVER_TAX_ACCRUAL` кратковременно регрессировал на 9820 (2026-07-05) — см. `Contador_CHANGELOG_FULL_v3.md`, разделы П1.2/П2.2/Н9.

### Покрытие TRANSIT-счетов (2026-07-05)

Все коды счетов, из которых строятся строки Формы №2, вынесены в именованные экспортируемые массивы в `pnl/route.ts`: `PNL_COVERED_TRANSIT_CODES` (реально участвует в расчёте, включая `REVENUE_ACCOUNT_CODES`/`COGS_ACCOUNT_CODES`/`ACCOUNTS.EXPENSE_*` из `constants.ts`), `PNL_ZERO_NET_TRANSIT_CODES` (используется шаблонами документов, но всегда нетто-обнуляется — сейчас только 9210) и `PNL_UNUSED_TRANSIT_CODES` (официальные счета НСБУ-21, которые пока не проводятся ни одним типом документа — 9140, 9150, 9220, 9910).

Тест `pnl-transit-completeness.test.ts` проверяет, что каждый TRANSIT-счёт из `seed-coa.ts` попадает в один из этих трёх списков, и что ни один тип документа не начал молча проводить через "неиспользуемый" счёт — если начнёт, тест упадёт и потребует явного решения о строке отчёта.

### Ответ API

```typescript
{
  period: { from, to },
  taxRegime: "VAT" | "TURNOVER_TAX",
  turnoverTaxRate: number,
  lines: { line010, ..., line270 },
  months: string[],
  monthlyRevenue: number[],
  monthlyNetProfit: number[]
}
```

### Интерфейс

- Выбор периода: текущий год / текущий квартал / произвольный диапазон
- Нулевые строки скрыты (кроме ключевых: 010, 030, 100, 220, 240, 270)
- Отрицательные значения в скобках красным цветом
- Динамическая подпись строки 250: `Налог на прибыль (15%)` или `Налог с оборота (N%)`
- Помесячная таблица выручки и чистой прибыли при периоде > 1 месяца

## G2. Форма №1 — Бухгалтерский баланс

**Файл:** `src/app/api/reports/balance/route.ts`  
**Страница:** `src/app/reports/balance/page.tsx`  
**API:** `GET /api/reports/balance?to=YYYY-MM-DD`

Полная реализация строк 010–780 по НСБУ №21.

### Источник данных

Кумулятивные остатки JournalEntry по дату `to` включительно (все документы, включая PERIOD_CLOSING).

Вспомогательные функции:
- `balDebit(...codes)` → `max(0, Σ_debit − Σ_credit)` — активные счета
- `balCredit(...codes)` → `max(0, Σ_credit − Σ_debit)` — пассивные счета

### Структура строк (сокращённо)

**АКТИВ — Раздел I:** Строки 010–130 (ОС, НМА, инвестиции, кап. вложения, долгоср. дебиторка)  
**АКТИВ — Раздел II:** Строки 140–390 (запасы, РБП, дебиторы, деньги, инвестиции)  
**АКТИВ итого:** Строка 400 = 130 + 390

**ПАССИВ — Капитал:** Строки 410–480  
Строка 450 — нераспределённая прибыль:
```typescript
// balCredit(8710) + transitNet (незакрытые TRANSIT-счета ≤ endDate)
// После YEAR_END_CLOSE: transitNet = 0
const line450 = line450raw.plus(transitNet);
```

**ПАССИВ — Обязательства:** Строки 490–770  
**ПАССИВ итого:** Строка 780 = 480 + 770

### Покрытие счетов (2026-07-05)

Как и на активной стороне, коды пассивной стороны (строки 410–760) вынесены в именованные экспортируемые массивы `LINE410_CODES`...`LINE760_CODES` и их объединение `BALANCE_PASSIVE_CODES` в `balance/route.ts`. Тест `balance-sheet-liabilities-completeness.test.ts` (по образцу уже существовавшего `balance-sheet-completeness.test.ts` для актива) проверяет, что каждый счёт типа `LIABILITY`/`CONTRA_LIABILITY` из `seed-coa.ts` попадает в этот массив.

### Балансовый контроль

```typescript
balanceCheck: line400.minus(line780).abs().lte(1)
difference: line400.minus(line780).toNumber()
```

### Интерфейс

- Выбор даты «на дату» (datepicker)
- Нулевые строки скрыты (кроме строк 130, 390, 480, 600, 770)
- Индикатор баланса: `Баланс сходится` / `Расхождение: N сум`

## G3. ОСВ (Оборотно-сальдовая ведомость)

**Файл:** `src/lib/reports/osv.ts` → `calculateOSV()`  
**API:** `GET /api/reports/osv?from=&to=&expandSubconto=true|false`

### Структура строки

```typescript
interface OSVRow {
  accountId, accountCode, accountName, accountType
  openingDebit, openingCredit    // начальное сальдо
  debitTurnover, creditTurnover  // обороты за период
  closingDebit, closingCredit    // конечное сальдо
  subconto?: OSVSubcontoRow[]    // если expandSubconto=true
}
```

### Алгоритм

1. Два SQL-агрегата к JournalEntry:
   - **Начальное сальдо** — по дате `< from`
   - **Обороты** — по дате `>= from AND <= to`
2. Рассчитать сальдо через `calcBalance()` по типу счёта
3. Строки с нулями пропускаются
4. При `expandSubconto=true` — разбивка по `counterpartyId`

**Ответ:** `{ rows: OSVRow[], totals: { sumDebit, sumCredit, ... } }`
